# shrineprayservice

## 概要

Spring Bootを使用した神社向け祈願予約管理アプリです。

神社の祈願予約をWebフォームから受け付け、入力内容をPostgreSQLに保存し、職員が予約内容を確認・編集・管理できることを目的としています。

また、管理者は職員アカウント管理や授与品管理を行えるようにしています。

現在は祈願予約管理を中心に、職員メニュー、掲示板、カレンダー、授与品管理など、神社業務全体を支援する機能を段階的に開発中です。

## 業務背景

神社で祈願を行う際は、祝詞で読み上げるため、事前に以下のような情報を把握しておく必要があります。

* 氏名
* ふりがな
* 住所
* 住所のふりがな（祝詞で読み上げる際の誤読防止）
* 生年月日（和暦）
* 願意
* 性別（厄年判断・初宮詣などで祝詞の内容が変わるため）
* 初穂料
* 初宮詣では両親の名前、会社祈願では会社名など、祈願内容に応じた追加情報

一般的な来店予約とは異なり、祈願内容や神社ごとの運用に応じて必要な情報が変わる点が特徴です。

また、祈願は予約を受け付けて終わりではなく、当日の受付、初穂料の確認、祈願済ステータスの管理、職員間の共有、将来的な崇敬者管理への連携までを含めて運用する必要があります。

## 願意について

願意とは、祈願における願い事のことです。

現在の区分は以下を想定しています。

* 無病息災
* 恋愛成就
* 家内安全
* 商売繁盛
* 学業成就
* 交通安全
* 開運厄除
* 子宝祈願
* 結婚祈願
* 長寿祈願
* その他

神社ごとの運用や特色に合わせてカスタマイズできる構成を意識して作成しています。

## 設計で意識していること

このアプリでは、以下のような責務分離を意識しています。

```text
Controller
  ↓
Service
  ↓
Repository
  ↓
DB
```

* Controller：リクエストの受け取り、画面遷移
* Form：画面から入力された値の受け取り
* Service：業務処理、予約更新、祈願済処理、件数取得
* Repository：DBアクセス
* Entity：DBに保存するデータ
* Model：画面や処理で扱うデータ
* DTO：画面表示用の集計データ
* Mapper：Entity / Model / Form の変換処理
* Utility：和暦変換などの共通処理
* Filter：ログイン状態確認などの共通処理

予約管理だけでなく、今後の機能追加を見据えて、画面・業務処理・DBアクセスをできるだけ分けて管理することを意識しています。
